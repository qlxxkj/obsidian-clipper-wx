# miniapp(微信小程序端:薄投递)

微信小程序是**薄投递端**:只做两件事——① 读手机剪贴板或手输 链接/视频/纯图文,② 点「投到收件箱」把它塞进 Cloudflare Worker 收件箱(`POST /v1/claim?code=xxxxxx`)。**不预览、不转换、不写库**——那些全在桌面 Obsidian 插件里完成。

原生 `wx` API,无构建,可直接导入微信开发者工具。

## 目录

```
miniapp/
  app.json / app.js / app.wxss       全局:路由(index + settings)、globalData(inbox/code)
  utils/api.js                       claim() 薄封装:POST /v1/claim
  utils/clipboard.js                 读剪贴板 → 提取链接 → 判断视频/网页/纯文本
  pages/
    index/     剪贴板自动读 + 网页链接/视频/纯图文 + 标签 → 投到收件箱 → 显示"已投,桌面端会拉取"
    settings/  填 收件箱 Worker 地址 + 6 位设备码,可测连接
```

## 自动读手机剪贴板

进首页(`onShow`)会**自动读手机剪贴板**:

- 有 `http(s)` 链接 → 填入「网页链接」模式;
  - 视频平台(B站/抖音/快手/视频号/YouTube)链接 → `kind=video`,桌面插件本地下载 + 抽字幕;
  - 其余链接 → `kind=url`,桌面插件 Defuddle 转正文。
- 没链接但有纯文本 → 填入「纯图文」模式(`kind=text`)。
- 读不到 / 被拒 → 显示「粘贴剪贴板」按钮,手动点一次再读。

分享文案里带链接(如 B 站「复制此链接分享」)也能自动抠出链接,不用手贴完整 URL。

## 使用

1. 微信开发者工具导入本目录。
2. **设置页**:填 Cloudflare Worker 的 HTTPS 域 + 6 位设备码(Obsidian 插件里「生成」拿到的那个)。
3. 开发期:devtools「详情 → 本地设置」勾 **不校验合法域名**。
4. 发布期:把 Worker 域加到小程序后台「开发设置 → 服务器域名 → **request 合法域名**」(必须 HTTPS)。
5. 首页投链接/视频/图文 → 提示"已投收件箱,桌面端 Obsidian 插件会拉取并写入"。

## 为什么小程序这么薄

小程序没有 DOM/JS 运行环境,也打不到 `127.0.0.1`,只能打加白 HTTPS 域。所以它不可能"读页面 DOM"或"直接写你电脑的 Obsidian"。重活放桌面插件、中间只留一个无状态收件箱,是这套架构最省的组合。剪贴板只是把"手机上复制"变成"自动填表",重活仍在桌面插件。
